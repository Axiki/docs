Lynka can enable or disable product areas for a workspace so the navigation reflects what the business actually uses. This is useful for a small team that wants Sales and Accounting without filling the sidebar with areas it does not need.

## Installed is not the same as entitled

A product area has to pass more than one check:

- the plan must allow it
- the workspace must enable it
- the user's role or explicit access must allow it
- the user's account must be active

Turning an area off in the workspace does not change the plan itself. Turning an area on cannot bypass a plan that does not include it.

## User navigation

The desktop sidebar and mobile More panel filter navigation using installed product areas, permissions, user access, and plan state. This means two users in the same workspace can have different navigation when their access differs.

## Owner control

Installed Apps is an owner-oriented setting in the current frontend. Use it to simplify the workspace, not as a substitute for individual permissions.

For example, if the company uses Accounting but a salesperson should not see it, keep Accounting installed for the workspace and remove that user's Accounting access. Do not disable Accounting for the entire workspace.
