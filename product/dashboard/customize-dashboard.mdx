The dashboard is a configurable working view, not one fixed executive report. Users can arrange the metrics, tables, charts, maps, tasks, and activity surfaces that matter to their role and access.

## Desktop dashboard

Desktop uses a configurable widget grid. Supported widgets can be moved and resized. Individual frames can expose a title, subtitle, period selector, refresh action, remove action, and widget-specific controls.

The dashboard action menu supports actions such as adding widgets, changing data scope, changing the hero or background where enabled, restoring defaults, and display or layout controls.

## Add a widget

Open the dashboard action menu and choose the add-widget flow. The available catalog depends on the plan, entitlements, permissions, and widget configuration.

Select the widget and add it to the layout. User-added widgets are persisted separately from fixed or default widgets so restoring defaults does not have to mean every custom choice is permanently lost.

## Data scope

Scope determines which records feed a widget. A user looking at Mine or team scope can see different KPIs from an owner looking at workspace scope.

Before treating two dashboard values as inconsistent, compare the period and scope on both views.

## Mobile dashboard

Mobile is not a shrunken draggable desktop grid. It uses a purpose-built vertical dashboard with mobile hero, summary rails, follow-ups, pipeline and lead-flow cards, quick actions, and other mobile components.

Desktop drag and resize is not the primary mobile interaction.

## Loading and refresh

Widget-local skeletons are intended for the first load before usable data exists. A background refresh should keep the existing widget visible and refresh in place rather than blanking the whole dashboard.

## Premium and plan-gated widgets

Some charts or advanced reporting surfaces can be gated by plan or entitlement. Basic dashboard charts are separate from the advanced Reports area in the current entitlement model.
