The Reports builder lets you compose and present supported report data without having to write database queries. It sits alongside the canonical catalog, not above it.

## Open the builder

Go to **Reports > Builder**. Access to the broader Reports area depends on the reports entitlement and user permissions.

The current UI supports domain filters such as All, Leads, Deals, Quotes, Invoices, Products, and Tickets, plus report search, scope controls, catalog or library selection, presets, layout, and widget display options.

## Choose a canonical source when one exists

If the business question already has a canonical report, start from it. For example, use the real Win Rate report rather than building a chart from arbitrary opportunity statuses and calling it win rate.

This protects important definitions such as close-date period logic, FX normalization, reporting exclusions, and recognized inventory cost.

## Save useful context

When saving a report or preset, make the title describe the question and scope. "Q3 Sales" is less useful than "Team pipeline by stage, current quarter" because the second name tells another user what the report is supposed to represent.

## Team and premium reporting

Some advanced or team report rows can show an upgrade prompt. Basic dashboard charts and the advanced Reports experience are separate capabilities in the current frontend.

## Mobile

Mobile stacks report surfaces and uses reduced tab or builder controls. Large report composition tasks are usually easier on desktop, but the access and calculation rules are the same.
