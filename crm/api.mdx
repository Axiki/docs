## Overview

The Lynka CRM API allows you to programmatically interact with your CRM data. Our RESTful API follows standard conventions and provides secure access to all CRM functionality.

<Info>
  **Base URL**: `https://api.lynka-crm.com/v1`
</Info>

## Authentication

All API requests require authentication using an API key. Include your API key in the `Authorization` header:

```
Authorization: Bearer YOUR_API_KEY
```

### Getting Your API Key

<Steps>
<Step title="Log in to your account**:
  Sign in to your Lynka CRM account.
</Step>

<Step title="Navigate to API settings**:
  Go to Settings > Security > API Keys.
</Step>

<Step title="Generate new key**:
  Click "Generate New Key" and provide a description.
</Step>

<Step title="Copy and store**:
  Copy your API key and store it securely.
</Step>

<Step title="Set permissions**:
  Configure permissions for the API key.
</Step>
</Steps>

<Warning>
  **Keep your API key secure**: Never expose your API key in client-side code or public repositories.
</Warning>

## Rate Limits

The API enforces rate limits to ensure fair usage:

- **Free accounts**: 1,000 requests per hour
- **Pro accounts**: 5,000 requests per hour
- **Teams accounts**: 10,000 requests per hour
- **Enterprise accounts**: Custom limits available

Rate limits reset hourly. Exceeding limits will result in a `429 Too Many Requests` response.

## Response Format

All API responses are in JSON format:

```json
{
  "success": true,
  "data": {},
  "meta": {
    "timestamp": "2023-01-01T00:00:00Z",
    "request_id": "unique-request-id"
  }
}
```

### Error Responses

Error responses follow this format:

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "details": {}
  }
}
```

## Core Endpoints

### Leads

Manage leads in your CRM system.

#### List Leads

```
GET /leads
```

**Parameters**:
- `page` (integer): Page number (default: 1)
- `limit` (integer): Items per page (default: 20, max: 100)
- `status` (string): Filter by lead status
- `source` (string): Filter by lead source
- `sort` (string): Sort field (default: created_at)
- `order` (string): Sort order (asc/desc, default: desc)

**Example Request**:
```bash
curl -X GET \
  "https://api.lynka-crm.com/v1/leads?page=1&limit=10" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Example Response**:
```json
{
  "success": true,
  "data": {
    "leads": [
      {
        "id": "lead_123",
        "name": "John Doe",
        "email": "john@example.com",
        "company": "Acme Corp",
        "status": "new",
        "source": "website_form",
        "created_at": "2023-01-01T00:00:00Z",
        "updated_at": "2023-01-01T00:00:00Z"
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 10,
      "total": 150,
      "pages": 15
    }
  }
}
```

#### Create Lead

```
POST /leads
```

**Request Body**:
```json
{
  "name": "John Doe",
  "email": "john@example.com",
  "company": "Acme Corp",
  "phone": "+1234567890",
  "status": "new",
  "source": "website_form",
  "notes": "Interested in premium plan"
}
```

#### Get Lead

```
GET /leads/{lead_id}
```

#### Update Lead

```
PUT /leads/{lead_id}
```

#### Delete Lead

```
DELETE /leads/{lead_id}
```

## Webhooks

Receive real-time notifications about events in your CRM.

### Setting Up Webhooks

<Steps>
<Step title="Navigate to webhooks**:
  Go to Settings > Integrations > Webhooks.
</Step>

<Step title="Add webhook URL**:
  Enter the URL where you want to receive webhook events.
</Step>

<Step title="Select events**:
  Choose which events you want to receive.
</Step>

<Step title="Test connection**:
  Verify that your endpoint can receive webhooks.
</Step>

<Step title="Save configuration**:
  Save your webhook configuration.
</Step>
</Steps>

### Webhook Events

| Event | Description |
|-------|-------------|
| `lead.created` | A new lead is created |
| `lead.updated` | A lead is updated |
| `lead.converted` | A lead is converted to an opportunity |
| `opportunity.created` | A new opportunity is created |
| `opportunity.updated` | An opportunity is updated |
| `opportunity.won` | An opportunity is won |
| `opportunity.lost` | An opportunity is lost |
| `quote.created` | A new quote is created |
| `quote.sent` | A quote is sent to a client |
| `quote.accepted` | A quote is accepted |
| `quote.rejected` | A quote is rejected |
| `invoice.created` | A new invoice is created |
| `invoice.paid` | An invoice is paid |
| `invoice.overdue` | An invoice becomes overdue |

### Webhook Payload Format

```json
{
  "event": "lead.created",
  "timestamp": "2023-01-01T00:00:00Z",
  "data": {
    "id": "lead_123",
    "name": "John Doe",
    "email": "john@example.com",
    "status": "new",
    "source": "website_form",
    "created_at": "2023-01-01T00:00:00Z"
  }
}
```

### Webhook Security

Verify webhook authenticity using the signature in the `X-Signature` header. The signature is computed using HMAC-SHA256 with your webhook secret.

## SDKs and Libraries

### JavaScript/Node.js SDK

Install the SDK:
```bash
npm install @lynka-crm/sdk
```

Usage:
```javascript
import { LynkaCRM } from '@lynka-crm/sdk';

const client = new LynkaCRM({
  apiKey: 'YOUR_API_KEY'
});

// Create a lead
const lead = await client.leads.create({
  name: 'John Doe',
  email: 'john@example.com',
  company: 'Acme Corp'
});

console.log(lead);
```

### Python SDK

Install the SDK:
```bash
pip install lynka-crm-sdk
```

Usage:
```python
from lynka_crm import LynkaCRM

client = LynkaCRM(api_key='YOUR_API_KEY')

# Create a lead
lead = client.leads.create(
    name='John Doe',
    email='john@example.com',
    company='Acme Corp'
)

print(lead)
```

## Error Codes

| Code | HTTP Status | Description |
|------|-------------|-------------|
| `INVALID_REQUEST` | 400 | Request parameters are invalid |
| `UNAUTHORIZED` | 401 | Invalid or missing API key |
| `FORBIDDEN` | 403 | Insufficient permissions |
| `NOT_FOUND` | 404 | Resource does not exist |
| `RATE_LIMIT_EXCEEDED` | 429 | Rate limit exceeded |
| `INTERNAL_ERROR` | 500 | Internal server error |

## Best Practices

### Authentication
- Store API keys securely, never in version control
- Use environment variables for API keys
- Rotate API keys regularly
- Use different keys for different applications

### Rate Limiting
- Implement exponential backoff for retry logic
- Monitor your API usage
- Batch requests when possible
- Cache responses when appropriate

### Data Handling
- Validate data before sending to the API
- Handle partial failures gracefully
- Use appropriate data types
- Include error handling in all API calls

### Webhooks
- Respond to webhooks quickly (within 10 seconds)
- Verify webhook signatures
- Implement idempotency to handle duplicate events
- Log webhook events for debugging
