You do not need to configure the whole workspace before Lynka becomes useful. Pick one workflow that matches real work in your business, finish it once, then refine the settings around it.

## If you need more customers

Start with [LeadGen](/leadgen/overview). Define the kind of prospect you want to find, run the search, review the result, and move the prospects you actually want to work into the Sales lifecycle.

The important lesson is that a generated prospect is not already qualified. The CRM work starts after discovery.

## If you already have prospects

Create or import a Lead, assign responsibility, schedule the next action, and [qualify the lead into a deal](/product/sales/leads/qualify-lead) only when it has passed your qualification process.

This teaches the most important Sales distinction in Lynka: Leads are evaluated; Deals are won or lost.

## If you already have customers and need to bill them

Create a Quote when you are proposing terms. Create an Invoice when an amount is actually owed. Record a Payment when money is received.

Follow [Quote to cash](/workflows/quote-to-cash) if you want to see the complete commercial sequence.

## If you sell stocked products

Create a Product, add the supplier relationship you need, create a Purchase Order, then record the real receipt with a Goods Receipt. Posting the receipt is the point where receiving becomes an inventory event.

Follow [Procure to stock](/workflows/procure-to-stock) before importing hundreds of products. It is easier to fix a workflow when you only have one test product.

## If finance is the priority

Start with the [Accounting overview](/product/accounting/overview) and [Invoice to ledger](/workflows/invoice-to-ledger). Learn the difference between operational documents and posted financial records before you begin adjusting journals or closing periods.

## If more than one person will use Lynka

Start with [Run Lynka with a small team](/teams/run-small-team) before inviting everyone.

Decide:

1. which product areas each person needs
2. what actions they need to perform
3. whether they should see their own records, a team, or the whole workspace
4. who owns each type of work
5. which approvals or manager reviews matter

A small team is easier to manage when access reflects actual responsibility rather than giving everybody Admin.

## After the first workflow

Once one real workflow makes sense, add the surrounding features that reduce repeated work: notifications, automation, reports, saved views, integrations, and owner controls.

That order usually teaches Lynka faster than spending an hour configuring colors, optional fields, and every status before a real record exists.
